# Voice Arranger

リモート収録で各自が手元で録音した音声（iPhone のボイスメモなど）を、ブラウザだけで

1. **タイミングをそろえる**（同期）
2. **長い間を詰める**
3. **話していない間のノイズと、他の人の声の漏れを下げる**
4. **音量をそろえる**（-16 LUFS）
5. **文字起こしをして、フィラー（「えー」「あのー」など）を見つける**（確認してから切る）

して、話者ごとの WAV と完成ミックスを書き出すツールです。
処理はすべて使う人の PC の中で行い、音声を外部に送りません。
（文字起こしを使うときだけ、初回に文字起こしのモデルを Hugging Face からダウンロードします。音声は送りません。）

> **使う人へ**: 共有された URL を Chrome / Edge で開くだけで使えます。使いかたは画面上の「使いかた」（[guide.html](guide.html)）を見てください。

- 対応ブラウザ: Chrome / Edge（Mac・Windows）
- インストール不要。静的ファイルだけで動きます（GitHub Pages などに置くだけで公開できます）

## 使い方

画面の上の 4 つの手順を、左から順に進めます（「次へ」ボタンで進めます。上の手順の名前をクリックすると戻れます）。

1. **音声を入れる**: 各自の録音（m4a など）をドラッグするか「ファイルを選ぶ」。名前を直して「自動で整える」
2. **聞いて直す**: タイミングをそろえ、長い間を詰めた結果が表示されます
   - 「▶ 再生」で聞く（「編集後 / 編集前」で切り替え）。上の全体図をクリック・ドラッグすると、その位置へ移動します
   - 間の詰め方は「控えめ / ふつう / しっかり」から選ぶ（数値で決めたいときは「細かい設定」）
   - 切りたい所は波形の上をなぞって選び、「切って詰める」か「◯◯の声だけ消す」。灰色の帯（詰める間）をクリックして「切らずに残す」にもできます。「↶ 元に戻す」でいつでも戻せます
   - 各話者の「だけ聞く / 聞かない」は聞くときだけに効き、保存には影響しません
   - 声がずれて聞こえるときは「声のタイミングがずれているとき」を開いて、開始位置を ±0.1 / ±0.01 秒ずつ動かす（自動で合わせた確かさが低い人がいると、最初から開いています）
   - キーボードも使えます: スペースで再生 / 停止、Delete で選んだ範囲を切る、M でその人の声だけ消す、Ctrl＋ホイールで拡大縮小、Shift＋ホイールで左右に移動、Ctrl＋Z / Ctrl＋Y で元に戻す / やり直し
   - 手で直した内容はブラウザに自動で保存され、同じ音声を入れると「復元する」で戻せます
3. **「えー」を取る**（任意）: 「文字起こしを始める」。初回だけモデルをダウンロードします（small で約 320MB）
   - 色の付いた言葉が候補です。**橙＝えー・あー など**（最初から「切る」）、**紫＝あの・その など**（最初は「残す」）
   - 候補をクリックすると前後が流れます。「切る / 残す」を選び、「次 →」で次の候補へ。キーボードでは ← → で移動、スペースで元の音、E で切った後の音、Enter で切り替え
   - ほかの人が話している最中の候補は、全体の時間は詰めずに、その人の声だけを消します
   - モデルの変更と、保存した文字起こし（`_transcript.json`）の読み込みは「文字起こしの設定」にあります
4. **保存する**: ファイル名を決めて「保存する」→ 保存先のフォルダを選ぶ（48kHz）
   - 保存前に全体を通して聞くとき、保存する内容や仕上がりの音量を変えるときは、下の折りたたみを開きます
5. 仕上げ
   - **GarageBand（iPhone / Mac）**: 話者ごとの WAV を、それぞれ別トラックの**先頭（1小節目の頭）**に置くと、そろった状態で並びます。iPhone 版では、曲の長さ（セクション）を「自動」にし、取り込んだリージョンのテンポ追従はオフにしてください。
   - **Audacity（Mac / Windows・無料）**: WAV を読み込み、`_markers_audacity.txt` を「ファイル → 読み込み → ラベル」で読み込むと、カットした位置に印が付きます。
   - そのまま配信するなら `_mix.wav` を使えます。

### 書き出されるファイル

| ファイル | 内容 |
|---|---|
| `名前_1_話者名.wav` など | 話者ごとの音声。48kHz モノラル。全員、開始位置と長さが同じ。各 -19 LUFS（モノラル測定） |
| `名前_mix.wav` | 完成ミックス。48kHz ステレオ、-16 LUFS、ピーク -1 dBFS 以下 |
| `名前_cuts.csv` | カット一覧（種類・話者・内容・元の時刻・削除した長さ・編集後の位置）。Excel で開けます |
| `名前_markers_audacity.txt` | Audacity 用のラベル（カット位置・音だけ消したフィラー） |
| `名前_transcript.txt` / `.srt` / `.vtt` | 文字起こし（編集後の時刻。切ったフィラーは除く）。文字起こしをしたときだけ |
| `名前_transcript.json` | 文字起こしとフィラーの判断（元の録音の時刻）。読み込み直しと評価に使います |
| `名前_report.json` | 同期結果・設定・音量・フィラーの記録 |

## 仕組み

- **解析は 16kHz、書き出しは 48kHz**。読み込みと再サンプリングはブラウザの音声デコーダが行います。
- **声の区間の検出**: 10ms ごとの音量を、そのトラック自身の雑音レベルと声の大きさを基準に判定します。他の人の漏れ声（自分の声より小さい）は拾いにくくしています。
- **同期**（共通の時計がない録音をそろえる）
  1. 2人ずつ、すべてのずらし方について「2人が同時に話している時間が、偶然より少ないか」を FFT で計算し、会話として最も自然になる位置を探す
  2. 「A→B の受け答えの間」と「B→A の受け答えの間」が等しくなるよう微調整
  3. 3組の結果を最小二乗でまとめる（ほかの組と矛盾する組は除外）
  - 3人以上で、どの相手とも確度が低い人がいるときは、ほかの全員の会話をまとめて1本にし、「誰かが話している間は黙っているか」で照合し直す（2人ずつより手がかりが多い）
  4. 長い収録では区間ごとに推定し、端末の時計のズレ（ppm）がはっきり出ていれば補正
- **間詰め**: 全員が黙っている区間のうち設定より長いものを、前後を少し残して詰めます。カットは全トラック同じ位置なので同期は崩れません。つなぎ目には 8ms のフェードを入れています。
- **ゲート**: 各トラックで本人が話していない間は音量を下げます（既定 -15dB）。
- **音量**: ITU-R BS.1770-4 で測定して正規化し、ルックアヘッド・リミッターでピークを -1 dBFS 以下に抑えます。
- **文字起こし**: Whisper（Transformers.js、WebGPU。使えない PC では CPU）を Web Worker で動かします。各トラックで本人が話している部分だけを 30 秒以内のかたまりにして渡し、それ以外の音は下げます（漏れ声と無音での誤認識を減らすため）。さらに、同じ時刻にほかのトラックの方がはっきり大きい部分の文字は、漏れ声として除きます。時刻は各トラックの元の録音の時刻で持つので、同期を調整しても文字起こしはやり直さずに済みます
- **フィラーの候補**（3つの根拠を合わせます）
  1. 文字起こしに出たフィラーの言葉（Whisper は「えー」を「A」と書くことがあるので、それも含む）
  2. 声はあるのに文字がない部分（Whisper はフィラーの多くを書き起こさないため）
  3. 高さと音色がほぼ一定のまま続く声（えー・あー・うーん・んー）。文の終わりの伸ばし（「そうですねー」）は除きます
  - 境目は、実際に声がある範囲に合わせてから、近くのいちばん静かな位置（10ms 単位）に合わせます
- **フィラーの切り方**: ほかの全員が黙っていれば、全トラック共通の時間軸から切ります（残す間は既定 0.2 秒以上）。ほかの人が話していれば、その人のトラックの音だけを消します。どちらの場合も、そのフィラーはその人のトラックで消音するので、詰めた間に音が残ることはありません

## 制約・注意

- 同期の精度の目安は ±0.1〜0.2 秒です（会話が長いほど正確）。ずれが気になるときは開始位置を微調整してください。
- ボイスメモの音質設定が「ロスレス」（ALAC）の場合、Chrome / Edge では読み込めません。「圧縮」で録音してください。
- 1時間 × 3本で 1〜2GB 程度のメモリを使います。
- Safari / Firefox では保存先フォルダを選べず、書き出し後のリンクから保存する形になります（動作は未確認）。
- 文字起こしの速さは GPU によって大きく変わります。WebGPU が使えない PC では CPU で動くため、かなり遅くなります。
- 文字起こしのモデルは base / small / large-v3-turbo から選べます。日本語向けの kotoba-whisper は、ブラウザ用（ONNX）の版で単語ごとの時刻が取れないため入れていません。
- フィラーの言葉そのものを話題にしている部分（「えー、とか言わないように」など）も候補に出ます。最終判断は確認画面で行ってください。
- 合成音声での確認しかしていません。実際の収録での精度は、下の「評価」の手順で確かめます。

## テスト

```
node tests/core.test.mjs                       # 単体テスト
python tests/make_test_audio.py out --minutes 10 --m4a --wav16k
node tests/core.test.mjs out                   # 合成した3人の会話で同期・間詰めを検証
```

`make_test_audio.py` は、録音開始のずれ・時計のズレ・漏れ声を含む3人の会話を合成します（numpy, scipy, ffmpeg が必要）。
ffmpeg がない場合は `--sr 16000` で作り、`truth.json` の各トラックの `files.wav16k` を `files.wav` と同じパスにすると、同じテストを実行できます。

## 評価（実際の収録でフィラー検出を確かめる）

1. 実際の収録（例: 10分 × 3人）を `data/` に置く（`data/` は git に入りません）
   - アプリの中で正解を付けるときは、アドレスの末尾に `?eval` を付けて開く（例: http://localhost:8000/?eval）と、手順3に「正解を付ける」が出ます
2. アプリで解析 → 文字起こし → 書き出し。`名前_transcript.json` ができます
3. Audacity で各人の**元の録音**を開き、フィラーを選択して Ctrl+B でラベルを付け、言った内容（えー、あの など）を入力する。「ファイル → 書き出し → ラベルを書き出し」で、トラックごとに `labels1.txt` などとして保存する
   - 全部が大変なら、5 分程度でかまいません（下の `--from` / `--until` で範囲を秒で指定。例: 10〜15分 → `--from 600 --until 900`）
4. 採点する

```
node tests/eval_fillers.mjs data/名前_transcript.json data/labels1.txt data/labels2.txt data/labels3.txt --from 600 --until 900
```

表示されるもの: 候補全体と「最初から切る」候補それぞれの適合率・再現率、根拠（文字・文字のない声・伸ばす音）ごとの当たりの割合、フィラーの種類ごとの検出数、境目のずれ（ms）、**誤って切る候補の一覧**、見落とした箇所の一覧。
モデルを変えて書き出し、同じラベルで比べてください（AmiVoice を追加した場合も同じ手順で比べられます）。
